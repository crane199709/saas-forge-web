# Domain Docs

## 布局

本仓库采用 single-context：

- `CONTEXT.md`：根目录领域术语和模型。
- `docs/adr/`：架构决策记录。

workspace 子包共享这套领域文档，不按包分别创建上下文。

## 探索前读取

- 阅读根目录 `CONTEXT.md`。
- 如果存在 `CONTEXT-MAP.md`，则按其指引读取与任务相关的上下文。
- 阅读 `docs/adr/` 中与当前工作相关的决策。
  多上下文布局下，也检查对应上下文的 ADR 目录。

文件不存在时静默继续，不提前建议补建。
由 domain-modeling 技能在术语或决策明确后按需创建。

## 术语与决策

Issue 标题、方案、假设和测试名称中的领域概念，
应使用 CONTEXT.md 定义的术语，避免使用其明确排除的同义词。

缺少所需术语时，先检查是否引入了项目不使用的概念；
确有缺口则记录为后续 domain-modeling 的输入。

方案与已有 ADR 冲突时，明确指出对应 ADR 和重新讨论的理由，
不得静默覆盖。
