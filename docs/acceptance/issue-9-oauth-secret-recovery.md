## 实现

在统一 Console 的原操作表格提供显式恢复按钮及确认框。按钮依据完整的后端原操作者操作记录和 `canRecover`，提交前重新查询；本机时钟不放行恢复。保留固定 Client 0.4.0 与既有 Soybean 底座。

无本地待核查请求时，使用正式 `recoverOAuthClientOperationRaw` 按原操作 ID 恢复。本地保留同类未知创建／轮换时，候选记录仅用于定位 Client，使用 `recoverOAuthClientSecretRaw` 让后端校验确切原请求键与 Client 的关联；只有成功后才清除该请求锁。关联被拒绝时不回退为另一笔恢复，不按名称或客户端时间猜测成功。

仅接受 HTTP 200、匹配的 Client ID、有效 ACTIVE 资源与非空 Secret。Secret 只在内存展示，复用一次展示／复制组件；关闭、离页、刷新、退出、身份变化及晚到响应的处理沿用工作区边界。新增恢复标记只保存操作 ID、Client ID、交付状态，不保存恢复请求键或 Secret；现有原创建／轮换请求记录格式保持兼容。

恢复请求发出前保存非敏感标记。未知结果、未识别的异常状态或存储失败保持关闭，不生成另一笔恢复。仅在收到契约明确的 409 CLIENT_SECRET_RECOVERY_NOT_ALLOWED 时撤回此次恢复标记，保留原请求锁，不自动回退或重试。刷新与同身份重新登录保留约束，其他身份不显示该标记。后台不会自动重试签发。权威记录未提供足以证明关联的恢复结果时，不能仅凭 `canRecover=false` 自动解除未知恢复锁。

确认框说明新 Secret 会替代本次签发、旧稳定 Secret 的原重叠截止时间不延长；中英文完整。恢复按钮固定在表格右侧，确认支持键盘操作，关闭 Secret 后焦点回到恢复标题。成功后刷新后端操作状态。
